# v0.8功能设计：约束多目标整定与冻结验证

日期：2026-10-25。本文保留实现前的功能规格；六项核心功能现已在0.8.0.dev0本地实现，实际用法与范围见[指南](V0_8_GUIDE.md)和[验收](V0_8_VERIFICATION.md)。下文“建议/待办”描述原设计，不代替实际验收；v0.7频域仍未实现，本轮尚未发布。

配套：[实验协议与指标](V0_8_EXPERIMENT_PROTOCOL.md) · [v0.7设计](V0_7_DESIGN.md) · [版本路线](ROADMAP.md)。

## 1. 产品目标与实际增量

用户的问题从“哪个控制器误差更小”深入到：**在规定的对象变化、延迟、噪声和执行器限制下，我有哪些可用参数？它们如何在误差和控制动作之间取舍？选定参数在未参与选择的工况上还能否满足要求？**

本版围绕一条完整任务链组织：声明要求 → 固定搜索与工况 → 比较可行候选 → 冻结选择 → 新工况验证 → 保存可复核的结论。

| 基础能力 | 当前局限 | v0.8增加什么 |
|---|---|---|
| v0.3预算整定 | 固定搜索范围，在3个名义训练场景中选一个NIAE最小值 | 用户定义条件与范围，在多个不确定工况上筛选，展示有限候选中的多目标取舍 |
| v0.6参数扫描 | 控制器参数全程冻结，观察现有参数的表现 | 将预声明的不确定工况用于候选评估；搜索结束后再冻结参数，不按网格点分别调参 |
| v0.6实验对照 | 比较保存的轨迹和配置 | 组织基线、候选选择、独立验证的关系，标明每项结论依据哪个阶段 |
| v0.7频域设计 | 计划提供单个标称工况的线性解释 | 将选定参数送去解释；未通过验收的频域接口不能显示为已接通 |

深度体现在约束、比较规则和验证流程。P0不依赖遗传算法、强化学习或复杂优化库；先用固定预算候选及非支配筛选，把行为做正确。

## 2. 首版边界

P0每个任务只处理一种对象、一种控制器结构。对象为现有一阶或质量-弹簧-阻尼二阶；结构为PI、PID_aw、TwoDOF_PID之一。基线由当前实验页的完整参数提供。

可搜索kp、ki，以及结构适用的kd、beta；微分滤波时间常数、抗饱和开关、初始状态、采样周期和执行器限幅冻结。每个搜索参数声明上下界及线性/对数尺度，允许固定参数。对数范围必须严格为正；beta必须在线性尺度的[0,1]内。零积分/零微分可以固定，或通过合法线性范围产生，不偷偷以小正数代替零。

工况采用1～2个不确定因素的有限网格，并与已选信号族、噪声种子组合。轴复用v0.6的合法字段：对象参数、测量延迟、噪声强度、非恒值扰动幅值；相同字段不能再被波形模板覆盖。采样周期不作为P0扫描轴。

P0不做跨算法排行榜、不宣称全局最优或连续参数域的鲁棒稳定性。LADRC整定、自动增密失效边界、自定义对象、频域裕度硬约束和断点续算列入P1或后续版本。原有整定、扫描和LADRC实验入口继续独立保留。

## 3. 用户可以完成的六个功能

### F01：把工程要求变成可计算的检查条件

输入：当前对象、基线控制器、固定单位及参考尺度，以及勾选的要求。

P0提供三个上限：逐工况归一化RMSE、饱和时间比例、归一化输入变化率。至少开启一个要求；任何执行失败或指标无效都自动使候选不满足要求。

界面同时显示归一化与物理单位，例如R=1 unit时，“归一化RMSE上限0.20，对应0.20 unit”；二阶位置输出则使用m，不能沿用电机单位。阈值是用户要求，软件不预设为行业合格线。

输出：一份冻结的要求表，包含阈值、单位、适用窗口、比较方向和等号规则。改变要求会创建新任务，旧结果保留。

恢复时间、超调量和输入能量暂不纳入P0硬约束：其适用信号与计算语义需要另行定义。已有恢复指标可以在明细查看；tracking_only中的空恢复时间不能按0参与比较。

### F02：在计算前给出完整预算与工况清单

用户声明候选数、搜索种子、参数范围、工况网格、信号族、噪声种子，以及事先固定的新工况验证方案。P0候选预算为2～128的整数（含基线，默认32），实际唯一数量在生成并去重后确定；最终仍受闭环次数和推进区间总预算限制。

开始前展开显示：唯一候选数量、搜索闭环次数、验证预留次数、总推进区间和每阶段保存内容。无效时间对齐、非法对象、重复输入工况或超预算在创建结果目录前拒绝；软件不静默删格、降密度或缩短时长。

候选0为用户基线，计入候选预算。搜索范围不包含基线时明确提示“基线仅作参照，不来自本搜索范围”，不得将其夹到边界。候选在运行前全部生成、去重并保存；重复候选保留别名与原序号，不重复计算、不临时补采样。

输出：冻结协议、候选清单、逐次运行计划及预估上界。示例任务最多858次闭环仿真，推导见配套协议；它是设计预算，不是已生成的结果。

### F03：显示误差与动作之间的可行取舍

主图横轴为搜索工况的误差目标J1，纵轴为最坏输入变化率J2。可行候选以实心点显示，有限候选中的非支配点突出显示；失败及不满足要求的候选保留在单独列表中，不能用有利的局部均值放进前沿。

鼠标点选一个候选后，同时更新：参数表、与基线的逐项差异、约束最紧工况、代表响应、实际输入。候选ID是关联主键，不能因表格排序而指向另一组参数。

可提供“较低误差”“较平稳动作”两个定位按钮：分别按(J1,J2,ID)和(J2,J1,ID)排序定位。软件不默认宣称存在唯一的“综合最佳”，不以任意权重把两个量合成隐藏分数。

非支配定义是：某候选在所有目标上不差、至少一个目标更好，才支配另一候选。这里只针对已评估的可行候选，不能称为连续搜索空间的完整Pareto前沿。[MathWorks多目标术语说明](https://www.mathworks.com/help/gads/gamultiobj-algorithm.html)

### F04：解释具体哪里不满足要求

候选详情给出“工况—种子—要求—实际值—阈值—状态”表，并能打开原始轨迹。最坏误差与最坏动作可能发生在不同工况，必须分别定位。

状态分为：满足要求、指标越限、运行失败、指标无效、未完成。一个候选有多项问题时全部保留。数值失败不能自动解释为物理失稳；较高饱和比例也不能单独证明失效根因。

当没有可行候选时显示“当前范围、预算和声明工况中未找到满足要求的候选”，并指出常见越限项；不回退到基线、不自动放宽阈值、不启动正式验证。用户可复制协议建立新任务。

P0只定位已有证据，不增加隐含诊断仿真。想隔离某个因素，需要另建明确的一因素配对实验；改变参数后仅凭两条曲线不能给出因果结论。

### F05：冻结参数后验证，防止用验证结果挑参数

搜索全部完成后，用户可以提名最多2个可行候选，并在读取验证结果前明确指定其中一个为“主选方案”。比较候选可以帮助记录取舍，但不能看完验证结果后再悄悄更换主选。

冻结记录保存候选ID、完整参数、搜索结果指纹、主选ID、验证计划指纹和软件版本。验证器只接收这份记录和固定的验证计划，候选选择器不能读取验证指标。

验证阶段运行主选、可选的比较候选以及基线。每个方案共享同一份对象参数、参考/扰动、噪声数组、限幅、采样和评价窗口。基线即使不满足搜索要求，也保留作验证参照；完全相同的参数只运行一次并记录别名。

输出“主选方案在声明验证工况中满足/未满足要求”的结论，不在验证页重新画一条用于择优的前沿。验证失败照常保存；想继续调参须建立新搜索任务，已经看过的验证集标记为“已观察”，不能重新命名后宣称未参与选择。

若验证结果或源文件被更改，重新核验指纹并拒绝沿用原完整状态。校验和用于发现变化，不是防止用户有意修改的安全机制，也不能证明第三方盲测。

### F06：把一套选择依据完整交给别人复查

报告明确区分搜索结果、选择理由、冻结记录、验证结果和可选频域解释。保存全部搜索原始轨迹与逐工况指标，不只保留赢家；验证也保存基线与候选的全部输入、CSV、状态及失败日志。

固定导出：可行候选取舍图、约束越限概览、基线与候选的输出/误差/实际输入对照、验证逐工况要求表；图表均保留PNG和SVG。报告中的“改善百分比”只比较同阶段、同工况的配对值，基线为0时不制造百分比。

图表标题带阶段、工况范围、单位和固定窗口。没有实际值的图不生成虚假曲线；取消和文件损坏保留明确状态。v0.6及更早的图片和报告不覆盖。

## 4. 交互组织

沿用现有“预算整定”入口，提供“经典协议”与“约束多目标”两种任务类型；不继续增加同等级顶栏按钮。旧任务读取时自动显示其原有协议，不能冒充新模式。

新模式采用五个步骤：

```mermaid
flowchart LR
    A[要求与范围] --> B[工况和预算]
    B --> C[搜索与候选取舍]
    C --> D[冻结主选方案]
    D --> E[新工况验证与报告]
```

- 左侧：对象与基线、任务阶段、来源及结果列表。
- 中央：大图；搜索时为真实进度，搜索结束为候选取舍，选点后切换响应/实际输入。
- 右侧：当前候选参数、要求检查、最坏工况、来源；不是一堆没有上下文的数字卡。
- 下方：紧凑参数设置或候选明细，可展开，不挤压曲线。
- 主要操作随阶段变化：“检查预算并开始搜索 → 冻结选择 → 运行验证 → 保存报告”。搜索与验证期间保留取消入口。

运行时显示“已完成X/计划Y次闭环运行”，报告保存单独显示阶段，不伪造总百分比。所有选项、错误、焦点、表格选择和按钮支持键盘操作；Windows缩放验收沿用v0.7。

搜索页的工况地图可借用v0.6视图。新验证工况若是显式离散列表，就显示列表/散点，不能画成没有真正运行过的完整矩形热力图。

## 5. 状态与不可变结果

| 阶段 | 可以做什么 | 不可做什么 |
|---|---|---|
| 草稿 | 修改要求、候选范围、两个阶段的计划 | 显示已验证结论 |
| 搜索中 | 查看完成进度、请求取消 | 根据中途成绩追加候选或改变要求 |
| 搜索完成 | 看全部候选、选择主选和比较方案 | 修改已保存的指标或读取尚未冻结的验证结果 |
| 选择冻结 | 按同一选择记录开始验证 | 原地替换参数、主选ID或验证计划 |
| 验证完成 | 查看并导出；发送选定方案到实验页或频域页 | 将验证后再选择的方案称为事先主选 |
| 取消/失败 | 看已完成证据、复制草稿新建任务 | 把缺失结果当作通过或重置成“从未观察” |

每阶段使用独立、不可覆盖的结果目录：搜索产物先独立完成；冻结记录引用其指纹；验证产物引用冻结记录。项目索引可以追加这些关联，但不能为了填新阶段而重写旧阶段的完整性文件。

取消搜索不产生正式前沿结论或可冻结选择，部分点仅供查看，标记“未完成”。取消验证不产生整体通过结论。P0不提供断点续算；同协议重跑记录来源，不算新的独立验证。

## 6. 与频域页和旧版本的关系

若v0.7接口已实现并通过验收，可把基线和选定参数分别送往标称频域分析。报告写明“在该标称模型未饱和条件下”的极点和裕度；它们不替代整个不确定工况集的时域要求检查。

本版P0不以相位裕度一个数自动淘汰候选，也不要求不支持的控制器伪造频域模型。若频域模块尚不可用，入口显示原因，其余设计仍独立可实现。

导入旧v0.3结果只能做历史参照，不能用旧候选日志冒充v0.8完整原始轨迹。v0.6已经观察过的扫描集可用于新搜索；未经说明不能再次包装为新的未观察验证集。

## 7. 实现分层与数据契约

以下为建议文件，尚未创建产品实现：

| 模块 | 责任 |
|---|---|
| `tuning_protocol.py` | 配置校验、候选与工况展开、输入指纹、预算；不读取任何结果 |
| `tuning_objectives.py` | 仅接收搜索指标，计算可行性、J1/J2及非支配集 |
| `tuning.py` | 执行搜索、全部轨迹保存、状态与完整性 |
| `tuning_validation.py` | 冻结选择、独立验证运行；不调用候选搜索/排序 |
| `tuning_plots.py` / `gui_tuning.py` | 从保存的数据构建图表与工作流 |
| `scripts/check_tuning_evidence.py` | 独立重算CSV指标、目标、前沿、配对和冻结顺序 |

建议配置版本为`tuning-config-1.0`，结果类型为`tuning-search-1.0`、`tuning-selection-1.0`、`tuning-validation-1.0`；当前读取器尚不支持，具体字段在实现前冻结。

配置至少包含：基础实验快照、控制器结构、搜索参数及尺度、候选生成版本/种子/上限、要求、两个阶段的完整输入计划、评价合同、候选提名上限、预算及来源。

搜索结果至少包含：所有候选和别名、每次输入指纹/轨迹/指标、可行性与逐项原因、J1/J2、前沿ID及全部状态。选择记录包含主选ID及完整参数；验证结果不得新增一个基于验证指标的“自动最佳ID”。

比较边界分三项记录：`artifact_complete`（文件是否完整）、`execution_complete`（计划是否执行完）、`requirements_met`（该阶段要求是否满足）。完整保存的失败报告仍可导出，三者不能合成一个含糊的绿色“成功”。

## 8. P0验收清单

| 编号 | 必须满足的行为 |
|---|---|
| A01 | 运行前能列出全部唯一候选、搜索/验证计划和预算；超限及非法参数无输出目录 |
| A02 | 相同协议产生相同候选与配对输入；别名不重复计算；基线不被裁剪 |
| A03 | 至少一个工况失败或越限，就不进入可行集；无可行方案不回退、不开始验证 |
| A04 | 独立CSV重算的归一化误差、输入变化率、饱和比例与保存值匹配 |
| A05 | 非支配集通过手工构造的支配、并列、近似值、空集及失败输入用例；不用显示舍入值排序 |
| A06 | 逐族权重、最坏种子及最坏动作的聚合均符合协议，不能因重复工况改变结果权重 |
| A07 | 单独改变验证指标不能改变已冻结的候选、主选ID、参数和搜索前沿 |
| A08 | 改动冻结记录/来源文件时验证被拒绝；相同输入换名字或零噪声换种子仍能检出复用 |
| A09 | 没有验证结果时无通过结论；取消/失败/损坏不能自动补0或假造完整状态 |
| A10 | 所有搜索和验证轨迹、图表及源码指纹归档；移走原来源后快照可读 |
| A11 | GUI选点与参数/轨迹正确关联；后台任务、取消、缩放和键盘操作通过真实交互验收 |
| A12 | 原有时域CLI、经典整定、扫描、跨实验对照及旧结果读取回归通过 |
