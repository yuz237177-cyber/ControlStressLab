# v0.8拟定实验协议：有限工况、多目标与冻结验证

日期：2026-10-25。本文保留运行前拟定协议。现已有按本协议保存的本机结果，见[实际验收](V0_8_VERIFICATION.md)；原拟定条目与实际配置分别保存。配套[功能设计](V0_8_FUNCTIONAL_DESIGN.md)。正式运行必须保存实际配置及版本，不能只引用本文默认数值。

## 1. 问题、比较单位与适用范围

比较对象为同一种控制器结构的不同参数候选；每次完整闭环运行是一个计算记录。配对条件为同一物理对象、参考/扰动数组、噪声数组、测量延迟、限幅、采样时序和评价合同。

种子仅改变声明的随机输入。一个时间序列中的采样点不是独立重复；确定性条件重复运行也不增加独立证据。有限工况、信号族和两条噪声轨迹不构成现实可靠性概率样本，不计算伪造的“95%可靠率”。

本协议使用完整有限交叉组合评估搜索工况，验证阶段使用预声明的新条件列表。所有候选共享这些条件，每次运行重置对象、控制器、延迟和随机输入。模拟器不存在设备随时间漂移时，固定运行顺序便于复现；不把运行顺序当作实验因素。未来接真实设备时需要重新设计区组与运行随机化。

## 2. 评价合同

每个场景固定评价起点a、终点b、实际推进区间Δt、参考尺度R>0、输入限幅U>0和单位。P0同一任务内所有场景共用R、U和采样周期，评价窗口可以按预声明的信号族不同而不同，不由候选表现决定。

对窗口内有实际控制动作的行计算：

```text
T      = Σ Δt
e[k]   = r[k] − y_true[k]
RMSE   = sqrt(Σ e[k]^2·Δt / T)
E      = RMSE / R
TV     = Σ |u_applied[k+1] − u_applied[k]|
V      = TV / (U·T)                              # 单位 1/s
Sat    = Σ Δt·1(|u_requested−u_applied|>1e−10) / T
```

TV只使用评价窗口内相邻实际动作；终端无动作行不制造新变化。饱和判据沿用现有实现的1e−10绝对差容差，并记录算法版本。P0是现有单位体系的扩展，此容差不宣称适用于任意数量级的自定义对象。

R是用户预先固定的参考尺度，不按某条参考信号的极差或候选输出自动变化。V是输入变化率，不能称为能耗、RMS输入或执行器寿命；这些需要另设指标。主要误差来自合成模型真实输出，测量噪声是反馈输入，不把它误当真实输出误差。

运行不完整、输出上限中止或指标无效：用于评分的E/V/Sat均为null；保留观察截止时刻和诊断，不按短窗口重算成更低误差。

## 3. 可行性

无论用户启用哪些阈值，全部声明搜索记录完整且三个基本指标有限是候选可行的前提。其后逐条检查启用要求：

```text
E[f,c,s]   <= error_max        # 可关闭
Sat[f,c,s] <= saturation_max   # 可关闭
V[f,c,s]   <= variation_max    # 可关闭
```

f为信号族，c为该族中的物理/波形条件，s为配对随机输入索引。至少启用一项阈值；要求适用于所有声明记录。等号视为满足，不在显示四舍五入之后比较，也不暗中放宽阈值。

可显示各记录原单位的越限量和单位；不把不同量纲的越限直接求和当“最接近可行”。无可行解只意味着此有限搜索未找到满足声明要求的候选。

## 4. 两个目标与前沿

仅对可行候选定义：

```text
E_worst_seed[f,c] = max_s E[f,c,s]
E_family[f]      = mean_c E_worst_seed[f,c]
J1               = mean_f E_family[f]         # 族等权的误差
J2               = max_(f,c,s) V[f,c,s]       # 最坏动作变化率，1/s
```

两个目标均越小越好。先按族内物理/波形条件等权，再对信号族等权；某族增加条件不能自动提高它的总权重。种子取最坏值而不是均值，以公开的保守描述减少偶然有利种子的影响；这仍是有限观察最坏值，不是噪声分布上界。

两个候选的前沿判定使用保存的完整精度J1/J2：A在两者均不大于B且至少一项严格小于，才支配B。不在支配规则里混入成对容差，避免近似关系不传递。完全相同目标的不同参数可以都保留，定位按钮再用候选ID确定性解并列。

原始输入重复不构成新的权重。展开后发现完全相同条件而ID不同，应在运行前拒绝并指出重复位置；候选相同则保留别名。所有聚合记录参与项与计数，独立审计可以从CSV重新计算。

选择器只接收搜索指标。验证结果没有传入该函数的参数或文件读取路径。图表题名使用“有限可行候选中的非支配集”，不宣称找到连续问题的完整Pareto最优解。

## 5. 候选生成

P0复用可复现的固定预算思路，候选0是原基线，其余由已声明的搜索种子、候选序号和参数名通过SHA-256映射到[0,1)后产生。线性参数使用a+(b−a)u，对数参数使用exp(log(a)+(log(b)−log(a))u)。映射细节、生成器版本及最终候选表一起保存。

候选在任何仿真结果出现前生成完毕，不根据中途成绩追加。固定参数原样复制，基线不会被范围裁剪。对相同完整参数进行规范化去重，别名只引用同一次评估；唯一数量在预算页面明确显示，不补采样凑数。

相同候选预算不是不同控制算法间严格公平的保证。本版每任务只有一种结构，不借该协议发布算法优劣排行榜。LHS、自适应优化等以后可作为新生成器，必须建立新协议并记录实际候选。

## 6. 首轮可实施案例与预算

以下一阶案例仅为待运行协议示例，具体阈值由用户需求确定。二阶可复用相同数量结构，把tau轴换成质量轴，并保存实际单位与基线；不默认将一阶阈值数值当作二阶要求。

- 一阶：gain=1，名义tau=1 s，零初态，R=1 unit；输入限幅±3，输出上限40 unit。
- Ts=0.01 s，时长12 s；全场景噪声标准差0.01R。微分滤波0.03 s固定；一个任务只选择PI/PID_aw/TwoDOF_PID之一。
- 最多32个候选，包含基线；参数范围与候选生成种子必须在正式配置中声明，本文不预告哪组范围能找到可行方案。

### 搜索阶段

物理条件为tau∈{0.8,1.2} s、测量延迟∈{0,0.04} s的完整2×2网格，其余对象参数固定。

| 信号族 | 参考与扰动 | 评价窗口 |
|---|---|---|
| 阶跃跟踪 | t=0.5 s参考阶跃至1R，无外扰 | [0.5,12) s |
| 变化参考跟踪 | t=0.5 s起正弦，偏置0.6R、幅值0.3R、0.29 Hz，无外扰 | [0.5,12) s |
| 扰动场景 | 同阶跃参考，t=6 s施加幅值0.2 unit的阶跃扰动 | [6,12) s |

两条噪声轨迹的种子为81011、81012。所有候选共享两条轨迹，不能每个候选重新抽一组更有利的噪声。扰动场景窗口可能保留起步残差，因此其误差不称为隔离后的纯扰动因果效应。

每候选4物理条件×3信号族×2噪声索引=24次闭环运行；32个唯一候选上限为768次。

### 冻结后的新工况验证

在搜索开始前即固定五组(tau_s,delay_s)：(0.9,0.01)、(1.0,0.03)、(1.1,0.05)、(1.35,0.02)、(0.7,0.06)。部分点超出搜索角点范围，报告标明是新的挑战条件；不将它们构造成未经运行的完整二维网格。

| 信号族 | 新参考与扰动 | 评价窗口 |
|---|---|---|
| 阶跃跟踪 | t=0.7 s参考阶跃至0.8R，无外扰 | [0.7,12) s |
| 变化参考跟踪 | t=0.7 s起扫频，偏置0.55R、幅值0.25R，0.17→0.73 Hz | [0.7,12) s |
| 扰动场景 | 同验证阶跃参考，t=6 s起二值块扰动，幅值0.18 unit、保持0.30 s | [6,12) s |

验证噪声种子82011、82012；对应的二值波形种子83011、83012。噪声和波形使用独立随机输入流，两者的数组都保存。具体波形起止、相位和样本对齐沿用已校验的信号生成器，正式协议以生成的实际数组为准。

每个被验证的唯一参数方案5物理条件×3族×2输入索引=30次。用户最多冻结2个可行候选，其中1个必须事先指定为主选；加基线上限为90次。

```text
搜索上限       32 × 24          = 768次
验证预留       (2候选+1基线)×30 =  90次
闭环运行上限                     858次
推进区间上限   858 × 1200       = 1,029,600个
```

若参数别名重复或只提名1个候选，实际次数减少，报告保存计划和实际差异原因。资源建议沿用1000次闭环与200万推进区间上限；正式版本可调整，但校验前须声明，不能到一半自动放宽。

频域解释、审计和图表不冒充闭环运行计数，应分别记录任务数、实际频点数及耗时，并遵守各自资源限额。保存全部原始轨迹所需空间在数值预研后用实际序列化样本估算，不能仅凭运行次数承诺压缩包大小。

## 7. 冻结和信息隔离

顺序固定为：两个阶段输入计划与要求冻结 → 完整搜索 → 保存完整搜索结果及校验 → 冻结主选/比较候选和验证计划指纹 → 验证开始 → 验证报告。

参数、要求、评价合同和验证条件都不能在查看验证结果后原地更改。若要修改，创建带父任务引用的新任务；已观察的验证条件进入开发资料，不再称为未参与选择。软件记录谱系与观察状态，但不能推断用户在其他软件里看过哪些数据，报告需保留这一边界。

跨阶段重复检查使用规范化的物理参数、初态、Ts/时长、限幅、延迟及完整参考/扰动/噪声数组的输入指纹，排除文件名、case_id、候选ID和随机种子的标签。只改名称或零噪声条件下只换种子，不能绕过重复检查。评价窗口与归一化尺度另有合同指纹，不把换窗口后的同一输入误称为全新激励。

新任务目录只是存储位置，不等于新证据。把同一冻结协议重跑只能称为复现；不能把它当成又增加一批独立样本。

## 8. 验证结论与结果保存

主要结论只针对事先主选：全部验证记录完整且满足全部启用要求，才显示“在声明验证工况中满足要求”。部分越限为未满足；运行失败、指标无效或未完成分别列出，不以其他点的好结果抵消。

比较候选和基线同样报告逐项结果，但不能在同一验证页按结果重新指定“正式主选”。若事后发现比较候选更合适，可以作为下一任务的起点，新的正式验证必须重新声明。

不根据验证结果自动换阈值、更新搜索前沿或返回候选生成器。计算验证阶段的描述性指标时使用本阶段合同，不能把搜索与验证不同波形/窗口的J1差直接称为控制器改进；改善比较必须在同一验证工况中对基线配对。

每个阶段使用独立结果目录、manifest/status/checksums和源码指纹。搜索保存全部候选的实际输入及轨迹；输入可按指纹共用一份，但不得丢失每条轨迹到输入的关联。冻结记录引用搜索产物和协议指纹；验证结果引用冻结记录。PNG/SVG、原始CSV/JSON、失败和取消日志均保存，完整状态最后写入。

## 9. 独立审计与验证计划

独立审计脚本不导入产品的评分、聚合、前沿计算模块，应从原始CSV和输入数组重新核对：计划数量、冻结参数、配对输入、评价窗口、RMSE/TV/饱和、可行性、J1/J2、非支配ID、主选冻结先于验证。

必须有负例：篡改RMSE后同步改文件checksum仍应被指标重算发现；把失败行改成0、删除难工况、改主选、仅更换case_id、重复零噪声种子、混入验证指标影响排序都应触发拒绝或审计失败。

对象动力学继续使用独立SciPy保持输入回放；PID请求和条件积分增加独立时序重算，覆盖饱和与解饱和。输入回放不等于独立非线性闭环认证，审计也不等于真实设备验证。

目前所有验收均为待执行。首轮先用人工候选和解析小案例验证规则，再冻结容差与代表案例；不根据完整案例结果不断放宽标准后宣称独立通过。
