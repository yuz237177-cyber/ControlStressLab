> 历史方案/阶段记录；当前已实现范围及交付状态以[v1.0桌面指南](V1_0_DESKTOP_GUIDE.md)和[最终验收](V1_0_DESKTOP_VERIFICATION.md)为准。

日期：2026-10-25。状态：**已启动构建，M1已实现并通过本机检查**。当前源码1.0.0.dev0；完整v1.0尚未发布。M2～M5仍为计划范围。已实现部分见[使用说明](V1_0_GUIDE.md)。

## 版本定位

把 ControlStressLab 从以预设动力学对象为入口的压力测试工具，推进为“定义对象 → 分析控制环路 → 多工况评估与整定 → 冻结验证 → 交付完整实验项目”的桌面工作台。

面向自动化专业学习、研究复现和方案比较，不绑定电机或轨道交通。v0.9界面作为视觉基线，v1.0主要改变建模能力、分析能力与完整使用流程。

## 当前基础和真正的缺口

已有：一阶/二阶桌面对象配置、四种控制方案、丰富波形、参数/延迟/扰动扫描、候选取舍、冻结后验证、轨迹与报告导出，以及新版GUI。库中另外存在电机对象，不能据此表述为GUI已支持任意模型。

进度：本轮已实现通用对象输入、开环预览及原有时域/扫描/整定/冻结验证接入。剩余缺口：v0.7频域仍停留在设计；实验目录之间已有来源关系，但还没有完整项目入口和可迁移的项目包；Windows分发仍依赖Python环境。

以上是建议的发布核心。采用分阶段验收，不把所有模块同时改写。

## A. 通用模型工作台

第一轮提供模型名称、输入/输出单位、分子和分母系数、采样条件与初始状态。界面显示公式、模型适用范围、开环响应及保存来源。内置一阶/二阶对象可以作为创建模板。

先完成1～4阶、连续实系数、严格真有理、无直接通道的SISO对象；状态空间矩阵作为内部可审计表示保存，直接编辑矩阵和离散模型导入后续再评估。

必须明确控制输入通道和对象扰动通道。不能把内置一阶的“增益乘控制输入”和“输出等效扰动”错误合并；没有定义扰动通道的自定义对象不默认拥有某个物理扰动含义。

不稳定开环对象、积分环节和负增益不能仅因“不像原预设”就一概拒绝；须区分合法模型、数值失败和闭环越界。资源/阶数超限或非因果模型应有明确拒绝原因。

首轮至少支持PI/PID族的完整时域流程。LADRC与各类通用对象的兼容范围需单独声明，不根据模型阶数自动猜测相对阶次、输入增益或稳定性。旧内置对象上的LADRC继续保留。

模型需要冻结成可追溯快照，图表和历史结果读取当时的参数与数值矩阵，不能跟随模型库中的后来编辑而变化。初始参考建议用标准一阶/二阶模板、带积分对象和高阶对象，逐一与独立工具核对。

## B. 频域与时域联动

继承[已有频域设计](V0_7_DESIGN.md)的数学口径与验收要求。新增频域入口，从实验、扫描工况或候选读取冻结配置；显示Bode、内部闭环极点、增益/相位裕度及灵敏度S/T。参考与扰动通道分别定义。

分析必须对应当前实际数字控制器、零阶保持和测量延迟，不能用连续理想PID图代替。存在多个交越、没有交越、频率奇点或内部不稳定时，保留明细和计算状态，不只输出一个容易误解的数字。

每类模型先核对无饱和、小幅值的逐点时域一致性，再接入GUI。时域压力实验含饱和、非线性分支、噪声和参数变化时，标称频域结论只作为解释，不替代多工况检查。

先打通原有一阶/二阶对象与受支持控制器，再接入通用模型。LADRC频域必须建立对应观测器与控制器的完整离散模型后单独验收，不能替换成近似PID。

## C. 项目级工作流程

一个项目围绕一个实验问题组织，包含：

1. 问题说明、模型快照与控制器方案。
2. 预声明的参考/扰动、参数范围、噪声、延迟及评价要求。
3. 单次实验、参数扫描和候选搜索的全部产物与失败记录。
4. 查看方案、主选/比较方案、取舍说明和冻结记录。
5. 新工况验证、可选标称频域解释与最终报告。
6. 全部原始轨迹、指标、图片、配置、来源指纹和运行版本。

项目主页可以显示阶段进度、最近结果和主要行动。已有大图工作区继续承担实际分析任务；不把全部功能压进一个固定向导，也不因美化隐藏原始数据入口。

项目索引关联独立结果目录，不重写已经冻结的结果。导出包使用可迁移的项目内引用和完整性清单；在不同用户目录解包后仍应能打开、查看和继续建立新的分析。旧记录保留自己的版本，新增结果记录新版本。

克隆方案或复制已保存参数后再整定，应形成新分支和新验证计划。不能把看过的验证结果重新称为未参与选择的数据。重新选择主选后必须产生新的冻结记录。

## D. 交付与稳定性

目标为无需安装Python的Windows桌面包。依赖、字体、中文路径、后台计算、报告打开、PNG/SVG与ZIP导出都属于打包验收范围，不以“打包文件生成成功”代替可用性检查。

提供三个完整、可复现的示例项目：

- 一阶过程：参数变化、延迟与扰动下的PI/PID比较。
- 二阶振荡系统：误差与控制动作之间的取舍。
- 自定义传递函数：从建模、分析到冻结验证的完整流程。

示例参数和轨迹明确标为合成仿真。没有硬件数据时不宣称完成实测验证。

保留v0.4～v0.9历史报告的只读打开与原单位显示；无法升级的旧格式给出具体说明，不静默重算旧指标。

## 开发顺序和验收关口

| 阶段 | 交付 | 通过后再进入下一阶段 |
|---|---|---|
| M1 模型底座 | 模型快照与兼容表、系数输入、通用时域执行器 | 与现有一阶/二阶逐点一致；独立对象回放、积分/负增益/越界案例通过 |
| M2 分析能力 | 标称采样闭环、频响与内部极点、线性时域核对 | 支持组合独立参考通过；对不支持/无交越/奇点正确标记 |
| M3 项目流程 | 项目索引、来源关联、选择理由、项目打包迁移 | 搜索/冻结/验证来源可审计；搬到另一目录可重开，旧记录不变 |
| M4 桌面整合 | 模型编辑页、频域页、项目主页和现有整定联动 | 通过真实操作、取消/失败路径、缩放、小窗口和键盘检查 |
| M5 稳定发布 | 便携包、三套完整案例、文档和发布候选 | 干净Windows无Python可运行，包内数据完整，回归与线上检查通过 |

M1已完成通用模型底座、桌面输入和端到端示例，通过逐点对照与独立回放。接下来按M2→M3→M4→M5推进；不承诺全对象、全算法兼容。

## 延后项

MIMO、MPC、大型拖拽框图编辑器、自动系统辨识、硬件实时闭环、云端协作和AI代理不列为本轮发布必需。Nyquist、根轨迹、直接状态空间编辑和LADRC完整频域作为核心完成后的独立候选扩展。

这些方向可以后续推进，但不能挤占通用模型正确性、项目完整性和桌面分发验收。

## v1.0完成的判断

第一次使用的人能在干净Windows上打开软件，从示例或自己定义的受支持对象开始，完成控制分析、声明要求、多工况整定、主选冻结和新工况验证，导出项目后在另一目录重新打开。每项结论都能追溯至模型、配置、原始轨迹与计算状态。

当前采用1.0.0.dev0标记开发阶段，保留旧实验与设计图；M1的实现不表示完整v1.0已达发布条件。稳定版本号、正式发布与上传需在后续里程碑验收完成后进行。


## 与v2.0论文目标的衔接

用户已确认以本科科研与复试展示为主、争取投稿。v1.0需预留可替换的工况采样器、全量预算日志、任务/重复分组及开发/最终验证隔离；不把现有工程能力直接作为新算法贡献。后续研究建议见[v2.0科研路线](V2_0_RESEARCH_PLAN.md)。论文目标不把全部软件扩展变成正式实验的前置条件。
