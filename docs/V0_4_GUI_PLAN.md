# v0.4 Windows桌面实验工作台方案

日期：2026-10-24。状态：前3轮已实现为v0.4.0，以需要Python环境的源码启动器与wheel发布；原计划的免Python便携分发留待后续。用户已选择Windows独立窗口。[实际截图与使用说明](GUI_GUIDE.md) · [验收记录](GUI_VERIFICATION.md)。以下保留设计目标，便携包验收条款对应后续分发，不表示当前wheel已通过该项。

## 1. 本版本解决的问题

现有工具已经能运行、保存和复核大量实验，但使用者需要修改命令和配置文件才能开展比较。v0.4的目标是：**在桌面完成对象配置、控制器对比、图表查看与证据保存，同时保持现有数值与证据链。**

建议版本主题：**ControlStressLab v0.4 — 桌面控制实验工作台**。

首版成功场景：第一次使用的人启动软件，选一阶对象和两种控制器，调整参考/扰动，运行后查看输出、误差和实际控制动作，再导出可复现报告；无需先理解文件结构或写命令。

v0.4不以增加控制算法数量为主线。v0.3新的独立诊断与稳健整定原型尚未由DeepSeek交付，不能把它们当成已完成算法。本轮DeepSeek成果验收实际覆盖DS007/008旧网格复核。

## 3. 用户界面

按用户提供的参考图改为深色桌面风格：**左侧实验配置列表 + 顶部功能导航 + 中央响应图 + 下方三栏参数 + 底部任务状态**。黑灰分层、蓝色强调，减少零散卡片。
主导航为实验对比、预算整定、历史实验；报告导出作为上下文操作，帮助放在侧栏底部。完整配色、控件状态和高DPI要求见[视觉规范](design/V0_4_VISUAL_STYLE.md)。

最新视觉调整：主要文字与参数数值加粗，响应曲线区占主工作区约三分之二；下方参数使用紧凑布局。曲线与数据阅读优先于参数面板占位。

### 3.1 实验对比

配置语义保留以下四组，视觉上合为“对象与控制器 / 参考与扰动 / 实验条件”三个下方分栏；常用项默认可见，高级项收起：

1. **对象**：一阶惯性 / 二阶振荡；显示方程、参数与单位。电机位于应用预设。一次实验固定一个对象，比较多个控制器。
2. **控制器**：PI、抗饱和PID、二自由度PID、LADRC；各自只展示有效参数。提供预设与恢复默认，不把预设叫“最优”。
3. **参考与扰动**：波形选择、幅值、偏置、事件时间与频率等；预览参考、扰动信号，显示采样保持含义。
4. **实验条件**：采样周期、时长、输入限幅、噪声、测量延迟、种子；评价窗口、恢复误差带与保持时长位于高级设置。

参数旁给单位和简短解释。例如二阶对象显示“输入限幅 / N”，一阶显示unit；不把兼容内核中的voltage_limit直接呈现成所有对象的“电压”。

持续变化参考自动选择合适的tracking_only语义，在结果中显示“恢复时间不适用”；不能用0秒假装恢复。参考/扰动组合与恢复判定仍要遵守后端校验，界面不能自行绕过。

表单修改仅更新草稿与信号预览。只有点击“开始对比”才运行；修改后已显示的旧结果标注“来自上一次配置”，避免把旧曲线误当新参数结果。

结果区至少包含：

- 曲线标签页：输出与参考、跟踪误差、实际输入；请求输入、测量和真实输出可按需显示。
- 指标表：IAE/RMSE、输入变化量或变化率、饱和比例、恢复状态与时间；无任意加权综合总分。
- 控制器曲线开关、缩放/平移、恢复视图、保存图片。
- 实际使用的配置和单位摘要；详细源码指纹放在“实验详情”，不占用初次操作流程。
- 导出报告、打开实验目录、保存配置。默认完整保存CSV/JSON，不因只显示一张图而丢弃其他结果。

最新深色设计稿：[PNG](design/v0.4-gui-dark-concept.png) / [SVG](design/v0.4-gui-dark-concept.svg)。草图里的曲线是布局占位，不是实验结果，也不是已实现程序截图。
早期[浅色草图](design/v0.4-gui-wireframe.png)保留作为历史设计，不再作为实现基准。

### 3.2 预算整定

提供“快速体验”和“完整v0.3实验”预设；默认不一打开就执行1152次。

- 只允许修改现有协议实际支持的对象子集、控制器、候选预算、种子、参数因子与训练约束。
- 当前协议固定的训练/测试波形、窗口和搜索范围明确展示为只读。实验对比页的自由波形配置不能被悄悄传入此协议后忽略。
- 开始前显示候选数、每候选训练场景数、训练次数、冻结测试次数和预计保存内容；不承诺未经测量的准确耗时。
- 运行中分为“训练 → 参数冻结 → 测试 → 保存报告”；训练界面不能显示提前计算的测试排名。
- 没有可行候选显示“未找到符合训练约束的参数”，列出约束，不自动放宽或静默回退。
- 结果显示baseline/tuned的误差和动作取舍，包括退化；禁止只显示改善百分比。
- 用户看过的测试结果再次用于改进时，标为开发/历史诊断；新的最终测试需要另行冻结。

### 3.3 历史实验

用户选择已有实验目录；软件只读取并展示。项目内索引可以是本机JSON，不为首版引入数据库。

- 显示对象、算法、场景、生成版本、成功/失败数量、产物是否完整。
- 读取报告保存的指标和单位，不用当前算法无声重算旧指标。
- 区分“校验通过”“校验不一致”“未提供校验”“文件缺失”，缺少清单不等于文件完整。
- 部分数据可读但校验失败时，允许查看并显著提示，禁止显示为验证通过。
- 先保证新通用格式、v0.3 benchmark和coverage可直接看曲线；早期uncertainty/stress-grid通过只读适配器或打开原离线报告提供访问。
- 旧电机CSV的列名必须根据其schema/单位映射，不能把rad/s自动改标为m。
- 不合并不同对象/评价窗口的指标后给出冠军；只有配置满足配对条件时，才提供逐项差值比较。

## 4. 技术选择

建议采用 **PySide6 + Qt Widgets + Matplotlib**，继续以Python作为唯一业务语言。

- PySide6是Qt的官方Python绑定，Qt Widgets提供桌面窗口与控件，适合这类参数面板与图表工具。[Qt官方入门](https://doc.qt.io/qtforpython-6/tutorials/basictutorial/widgets.html)
- Matplotlib支持在PySide6等Qt绑定中嵌入图表，能复用现有数据和PNG/SVG导出习惯。[官方Qt嵌入示例](https://matplotlib.org/stable/gallery/user_interfaces/embedding_in_qt_sgskip.html)
- GUI进程与计算子进程分离；Qt的QProcess提供进程启动、输出读取与退出通知。[QProcess文档](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QProcess.html)

与备选相比，这是针对本项目的工程选择：

| 方案 | 适配判断 |
|---|---|
| PySide6桌面 | 推荐。独立窗口、参数面板、任务管理和本地文件访问符合用户选择；需要专门验证安装包 |
| Tkinter桌面 | 依赖较少，但本项目的复杂图表面板和界面打磨仍需投入，不作为首选 |
| Streamlit本地浏览器 | 适合快速数据面板，但交互采用脚本重跑模型，需要管理运行状态；与本次独立桌面窗口目标不同 |
| Electron及独立Web前端 | 当前会增加前后端和打包工作，首版没有足够收益 |

Streamlit的重跑与状态机制见[官方执行流程](https://docs.streamlit.io/develop/api-reference/execution-flow)。不在本版同时维护桌面和浏览器两套GUI。

GUI依赖通过可选`[gui]`安装，核心CLI继续保持无必需第三方运行依赖。开发与Windows打包优先Python3.12；GUI支持范围按实际依赖和测试矩阵声明，不为了GUI无依据地改变核心的Python>=3.10承诺。当前机器尚未安装/验证PySide6，本文件不声称安装包已经能运行。

## 5. 后端先补齐的接口

当前`benchmark.execute`、`coverage.execute`等以批次导出和stdout进度为主，缺少统一表单配置、结构化进度和取消接口。现有绘图模块还会选择Agg后端；不应直接在GUI主线程运行整批实验。

建议职责分为四层：

```text
桌面界面：输入、预览、显示状态和图表
    ↓
运行服务：校验/冻结配置、分配新目录、启动子进程、取消和事件
    ↓
现有仿真/控制器/指标 + 场景对比与预算协议
    ↓
结果目录：配置、轨迹、指标、状态、图表、校验清单
```

### 5.1 配置服务

建立带schema版本的ExperimentSpec，显式记录对象及参数、控制器列表、信号、采样、噪声/延迟、单位、限幅、评价窗口和种子。

- GUI和新增CLI入口使用同一解析、校验、运行服务；不复制第二套控制算法。
- 新的自由场景对比通过通用runner实现，不能只改GUI字段却仍使用coverage写死的波形。
- 运行开始前冻结完整配置并保存指纹；运行时编辑草稿不改变正在执行的实验。
- 非有限数、非法参数、未对齐事件、样本量上限、观察器采样保护均由后端统一验证。
- 信号预览、实际仿真和导出使用同一已校验配置；采样参数无效时不自动四舍五入或悄悄截断。

### 5.2 运行服务和状态

首版同时只允许一个活动任务，避免多个实验抢占界面与文件。

状态至少区分：等待、校验中、运行中、请求取消、已取消、完成、完成但有运行失败、执行失败/产物不完整。

- 使用结构化事件传递阶段、已完成次数、总次数、失败数和当前场景；旧stdout日志进入可展开详情，不能解析任意自然语言来决定成功。
- GUI保持响应；耗时仿真和批量绘图在worker子进程中执行。worker使用Agg，GUI嵌入式图表使用Qt后端，避免同进程切换全局绘图后端。
- 取消在完整单次运行之间检查，最迟下个检查点生效；单次运行耗时较长时显示“等待当前运行结束”，不得在点击瞬间伪称已取消。
- 协作取消时保留已完成数据，产物完整标记为false；预算选择尚未冻结时不能开始测试。具体取消异常应由统一服务映射，旧CLI没有取消请求时保持原行为。
- 强制终止只用于失去响应的worker，独立记录异常中止；不能把进程退出码0或进度100%当作完整报告的唯一依据。
- 状态更新应原子写出；GUI读取到写入中的暂态不直接报告数据损坏。
- 运行管理自己的job状态与实验status分开，避免GUI在校验值生成后改写实验status导致自损校验。

### 5.3 结果读取服务

按schema选择适配器，统一供GUI读取通用轨迹、指标和单位；旧实验保留原定义。绘图可以对显示采样降密度，但计算与CSV仍使用完整数据；任何显示抽样需记录规则，不能由抽样数据重算指标。

### 5.4 导出和路径

每次实验分配不存在的新目录，不覆盖历史。文件写在用户选定的数据目录，不写进程序安装目录。

一次实验的报告、配置、原始轨迹、所有默认图和校验值一起保存；单独“另存这张图”另选目标。ZIP在最后打包并逐项校验。

## 6. Windows双击包

先完成可安装的Python GUI，再制作便携目录ZIP。用户解压后双击`ControlStressLab.exe`启动，所有所需依赖随包提供；不把电脑已安装的Python路径写死进去。

部署工具先评估官方`pyside6-deploy`的standalone模式，它通过Nuitka生成可执行文件与依赖目录；onefile会在启动时解包，首版不必强求单文件。[官方部署说明](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html)

发布包验收必须在未安装项目Python环境的Windows机器或干净虚拟机执行，验证中文/空格路径、离线启动、Qt插件、绘图、报告保存和worker启动。机器具备开发环境时能启动不等于便携包验收通过。

包内保留依赖版本和许可证文件、演示预设及使用说明。完整历史实验ZIP可另行下载；不要把全部大规模归档塞进首个程序包。

## 7. 分轮开发

### 第1轮：配置和运行服务

实现ExperimentSpec、单对象多控制器runner、结构化事件/取消、通用结果读取；原CLI保持可用。先核对相同输入下与现有simulate的结果一致，再做界面。

交付：服务接口、最小CLI、针对错误配置/配对/取消/失败/不覆盖的有效测试。

### 第2轮：桌面实验对比

按最新深色稿实现配置侧栏、顶部导航、中央曲线与下方三栏参数、信号预览、开始/取消、指标表和报告导出。第一版先支持一阶和二阶，使用公共单位。

交付：可实际运行的GUI、真实截图、从开始到导出的演示流程；不是只展示静态曲线。

### 第3轮：预算整定与历史

接入v0.3已存在的协议和阶段状态，读取benchmark/coverage归档；历史电机扫描能打开原报告。展示训练/测试退化和无可行候选，不把GUI包装成新优化算法。

### 第4轮：Windows分发与发布

完成离线便携包、干净环境试运行、README/使用文档和GUI测试；证据充分后才标v0.4.0。

DeepSeek适合独立复核配置映射、CLI/GUI结果一致性、异常流程、图表和分发文档；Codex负责公共接口与产品整合，避免双方同时大改同一后端。

## 8. 发布验收清单

1. 不使用命令行，能从启动完成一阶和二阶各一次多控制器对比并导出。
2. GUI与同服务CLI使用完全相同的冻结配置，逐采样轨迹/指标在预定容差内一致；配对噪声、限幅和窗口相同。
3. 界面修改确实影响运行；没有忽略的字段、旧图冒充新图或不合法参数自动修正。
4. 运行时界面可响应，取消能保留已完成数据；中断、失败和未找到可行参数的界面状态准确。
5. 错误配置、写入失败、损坏/缺失历史文件有清楚提示，失败指标不填0，校验结果不被美化。
6. 真实输出、测量、请求与实际输入、单位、恢复不适用等定义与后端一致。
7. 保存PNG/SVG、全部轨迹与配置、离线HTML和ZIP；关闭软件后能重新打开查看。
8. v0.3预算协议的先训练、再冻结、后测试顺序保持，未把原型研究结论冒充产品功能。
9. 原131项核心测试仍通过；新增服务/worker/GUI测试针对真实风险，不堆镜像实现的测试。
10. Windows桌面实际交互验收；Linux可做服务与必要offscreen GUI检查，但不能代替Windows双击包试用。
11. 干净Windows环境离线双击成功；中文路径、字体、图片、Qt依赖、worker和输出位置均实测。
12. README明确合成模型与实测边界，给出真实界面截图、便携包入口、使用步骤和证据限制。

## 9. 当前决策

已确认：Windows桌面方向；先做现有功能的完整可视化使用流程。

推荐采用：PySide6、Qt Widgets、Matplotlib，计算子进程与界面分离，先便携目录包。

已完成：公共实验服务、GUI与后台进程、交互测试、本机依赖安装、v0.3协议接入与历史查看。实际界面见[运行截图](design/v0.4-gui-running.png)。静态草图保留作设计历史。

v0.4.0首先发布需要Python环境的桌面软件。尚未完成：免Python的Windows便携可执行构建及干净机器离线验收。当前自由配置页聚焦一阶与二阶，旧电机案例通过历史原报告查看；强制结束失去响应的进程等高级任务管理也未提供。
