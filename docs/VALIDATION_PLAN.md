# 可信度与验证计划

## 当前证据状态

当前全部电机参数和测试条件为 synthetic_assumption。
没有真实电机测量、参数辨识结果、实物闭环验证或工业认证。
软件测试通过不能把这些状态自动升级。

## A. 工具正确性

已提供可执行校验：一阶对象解析解、约化电机的独立公式、保持输入分步一致性、
测量延迟时序、控制器噪声配对、执行限幅、抗积分饱和、未恢复处理、失败运行处理及 CLI 冒烟测试。
这些测试检验实现与定义，不证明现实有效性。

待补充：与 python-control 或其他独立实现对照；对更多控制周期和非零微分参数开展检查。
对象精确推进与控制周期收敛应分开讨论，不能随意改变 dt 后就把所有变化称为积分误差。

## B. 模型现实有效性

采集实际输入电压、编码器原始计数/转速、单调时间戳、采样周期、负载状态及设备信息。
校验单位、编码器分辨率、时间同步、丢样、驱动器限制和预处理。
按独立完整实验批次区分建模、模型选择和最终验证数据，避免相邻样本随机拆分。
除一步预测外，比较未用来拟合的输入下的完整自由仿真响应，检查误差、残差结构、工作点和负载范围。
预先结合测量误差与目标用途定义可接受标准，不使用通用的“拟合率达到某数值就真实”的判断。
反复用同一验证集挑选模型后，该集不再是最终独立检验，需要另外保留数据。

## C. 控制结论实物验证

把两个控制器分别部署至同一设备，在可重复条件下完成真实闭环运行。
固定调参预算、目标、采样和执行限制，记录实验顺序及设备状态。
比较完整运行的指标和变异，完整披露失败。
历史日志只能支持相应模型/指标检查，不能给未实际执行的新控制器提供反事实闭环证据。

## 结论允许范围

| 证据 | 可以说什么 |
|---|---|
| 实现校验 | 程序在已检验案例中符合方程及定义 |
| 合成仿真 | 指定模型、参数与场景下的性能变化 |
| 独立实测模型验证 | 在明确设备与工况范围内的模型误差 |
| 实物闭环 | 在实际执行过的设备/工况下的控制表现 |

单一电机案例不能替所有设备背书。更高保真仿真或硬件在环也不自动替代实体对象验证。
