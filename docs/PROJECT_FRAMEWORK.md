# 整体框架与范围

## 项目问题

使用者已有一个控制器，希望知道它在负载扰动、测量噪声、延迟和执行器约束下的表现。
工具提供统一的闭环执行、场景记录、指标与报告，不替用户断言工业适用性。

## 主要用户

已有控制算法、希望方便比较实验结果的学生和开发者。配套教程帮助理解控制与测量之间的区别。
项目同时服务于作者的专业学习与考研复试，个人贡献应能定位到模型实现、执行时序、实验协议和验证证据。

## 六模块

1. 被控对象：输出状态、接受实际输入与对象扰动、推进时间。
2. 控制器：只接收参考值、可用测量和采样周期；接受实际执行输入反馈。
3. 场景：定义参考信号、负载、测量过程、执行限制、评价窗口及来源。
4. 执行器：重置状态、组织采样、实现限幅与延迟、检测终止条件。
5. 指标：固定定义与窗口，失败或未恢复不记为零。
6. 报告：同时保存曲线、数值、配置和证据范围。

## 第一版设计决定

- 通用协议，电机专用演示 CLI；CLI 的 CSV 列名及单位为电机案例约定。
- 精确更新约化线性模型，避免第一版把数值积分误差混入控制器比较。
- 不加入自动调参、强化学习、综合评分、硬件驱动或实时性承诺。
- 固定采样，事件与延迟必须落在采样网格上；不静默四舍五入。
- 故意采用小而完整的功能范围，优先检查时序与结果含义。

## 成功标准

陌生人在普通电脑上按 README 跑通演示；能够查明每个数字对应的输入、模型、场景和时段。
至少一个简单对象能以独立解析结果核验。模型实测验证仍是后续独立交付，不因软件测试通过而视为完成。

## 技术选择

Python 3.10+，标准库，源码布局，命令行入口，CSV/JSON 记录，离线 HTML 报告。
报告内联 SVG 是快速预览；论文或正式报告应从 CSV 使用标准绘图工具重新绘制带完整坐标轴的图。
